# Explicit first-city transport

CLIENT-FIRST-CITY-GATEWAY-001 (#2495) exposes GatewayClient.requestFirstCity for the four world.v2 routes only when explicitly invoked.
Request shape is the adopted request codec shape; options accept signal, timeoutMs (default 15000) and optional knownIntent {scope, proposal} for exact Get C1 correlation.
Only this channel's strict Discovery response establishes lossless scope. It is bound to the socket/session/generation/shard; new Discovery supersedes old channel waits. Login/entry in progress cannot use old credentials.
The strict raw binary envelope precedes payload decoding. Error, abort, malformed response or lost connection rejects with fixed UNKNOWN, never durable rejection, raw server text or automatic retry.
Scope is an equality guard, not authority. ID_CONTENT_CONFLICT preserves the server's original record; different winners are never automatically continued.
The transport owns no journal and generates no command UUID. Before first Submit/Continue, a downstream consumer must crypto-generate a UUID, save the complete intent under its complete scope, and successfully read it back; an argument name or boolean proves nothing about storage.
Existing durable intent and terminal knowledge remain the consumer's responsibility and must survive UNKNOWN/EMPTY/NOT_OBSERVED. Authentication invalidation only clears this channel's temporary scope and waits.
Tests use actual production GatewayClient; native tests use Node WebSocket with a controlled ws loopback peer. They are not Chromium or real V2 handler/city creation evidence. No UI, v1 fallback, server activation or production deployment is included.

## Persistence-guarded entry (#2503)

GatewayClient.requestPersistedFirstCity has the same four-route inputs/options, with a privately owned, lazily opened localStorage journal. Submit/Continue store complete request bytes and C1, then actually read, validate and reconstruct the outgoing intent before sending. Correlated response payloads are saved and read back before returning. No packet/session/credential is stored.
readFirstCityHistory(scope) returns frozen intents, observations and unavailable. Entries use version1 closed JSON {version,kind,route,data,c1}, bounded lowercase hex, and keys sanguo:first-city:v1:realm:shard:player:account:random-entry-UUID. Entry UUIDs are storage identities, not new command IDs. Strict adopted codecs verify restored scope/content. Append-only independent keys prevent tab writes replacing one another; identical evidence is reused only after another actual readback.
Observed missing/changed/corrupt data or storage failure makes that live scope sticky unavailable and blocks guarded effect sends. All valid memory evidence survives, including a terminal response learned before a failed write. UNKNOWN, EMPTY, NOT_OBSERVED, login and current-view clearing never erase retained facts. Complete external deletion across restart is undetectable; an empty local history is never authoritative EMPTY.
This boundary preserves observations without ordering/reducing them or granting command eligibility. The next explicit controller must crypto-generate command UUIDs, arbitrate INITIAL/exact rejected predecessors, reject contradictory histories, retain terminal knowledge, display a different winner and require another explicit Continue, and isolate stale views/actors. Raw requestFirstCity still performs no persistence and must not be mistaken for this guarded entry.
Browser storage is writable local evidence, never authenticated ledger authority. Fresh authenticated Discovery and server revalidation remain required; no restored response grants execution or current-city access.
Local tests exercise real GatewayClient with controlled sockets and Storage doubles, not browser persistence. Independent official-CI native localStorage/reload/two-tab acceptance is tracked by #2504 and required before final readiness. V2 server handlers and the UI remain absent; no automatic request, legacy fallback, city entry or deployment is added.
