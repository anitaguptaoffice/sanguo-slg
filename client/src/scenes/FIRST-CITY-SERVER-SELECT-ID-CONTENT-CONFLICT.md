# ServerSelect ID_CONTENT_CONFLICT intake display

CLIENT-FIRST-CITY-ID-CONTENT-CONFLICT-001 ([#2708](https://github.com/anitaguptaoffice/sanguo-slg/issues/2708)) stacks on #2706.

Loopback ServerSelect V2 first-city panel shows **read-only** rows for retained `idContentConflict` observations from
Submit/Continue: the requested command id and the observation's **server original record** (canonical name/coordinates).
Canonical winner, losing-proposal, local-draft and HEAD_CONFLICT lines remain separate. Stale-actor, unavailable and
incomplete evidence withhold the display. No automatic Continue/Submit, no main-city navigation, no playable-first-city claims.
