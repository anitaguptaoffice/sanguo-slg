# Hero force cache storage failure handling

CLIENT-HERO-FORCE-STORAGE-001, issue #2385. Optional sessionStorage must not turn an accepted GetHeroDetail or RestHero result into a UI failure. Accessing the browser storage property, reading and writing can all throw. The cache now catches each operation, and unknown/unavailable snapshots leave StartMarch validation to the server. There is no automatic mutation, retry, fabricated force recovery or change to the existing 180-second advisory expiry.

A failed write or clear records an in-memory per-hero tombstone. Merely catching a quota exception would retain an older low-force entry and wrongly block the next march. That entry remains unknown even when storage access recovers, until a later successful write/clear for that hero supersedes it. Other heroes and explicitly supplied storage instances remain independent. Reads do not mutate storage. Tombstones are process-local and do not survive a full reload; the existing timestamp expiry still bounds authority after reload. This is not cross-account storage redesign or durable persistence.

Observation revisions advance even when persistence fails, so a delayed rest cannot overwrite a newer observed detail or clear. Default calls share a stable in-memory scope, including while the sessionStorage getter is unavailable. Explicit storage arguments use their own scope; explicit null disables the cache. Normal production callers use the default scope.

Regression coverage uses actual helpers and mounted HeroMailPanels with controlled gateway results: getter/read/quota failures, detail and rest success, stale low-value suppression, recovered writes, per-hero/store isolation, invalid IDs and delayed-rest fencing. On unchanged main, the new tests produced 11 expected failures and one passing control. Focused/full tests, build, independent review and exact-head CI are recorded in the PR. These deterministic tests are not native browser/storage-policy or live-server acceptance; no visual behavior changes, native launch retry, deployment or historical hold release is included.
