# Existing account entry

The new explicit account/password form logs into the selected available server and loads an already-owned city. It sends Login, EnterGameServer, ListPlayerCities and GetCityState. It never calls Register or CreateCity, including after a login failure. There is no automatic fallback to the demo identity.

If no owned city exists, entry stops with an explicit unfinished-first-city notice. This is not new-player onboarding. The server's existing Login may create a character/wallet for a previously unused shard; this change does not alter or claim to suppress that existing behavior.

The separate existing demo button and its provisioning behavior are preserved. The two buttons share single-flight entry. Credentials/server are captured before the request; pending entry disables both buttons and credential changes. Stale actor responses cannot produce a new scene.

The application does not write credentials to storage or logs. The password field is cleared on submit, dismissal and scene departure. Browser/password-manager behavior is controlled separately by the browser; autocomplete=off is not a guarantee against external password-manager retention. The actual default GameApp gateway configuration must be wss, or a loopback ws development endpoint, before the new form submits credentials. No fallback downgrades transport.
