# Natural explicit registration acceptance

The dedicated scenario is called by the independent `.github` registration runtime. It consumes new disposable credentials which must not exist before the browser clicks Register. No pre-created account substitutes for that registration. Known a/b accounts are separately provisioned fixtures used only for existing-login comparisons.

Every socket is connected to the actual server and packets are forwarded unchanged. For the lost-reply scenario only, the successful real Register receipt is recorded as safe numeric metadata but not delivered to the browser; the socket closes. PostgreSQL must corroborate that actual account with no player or city. No synthetic success, DOM injection, fake clocks or backend mutation substitutes are used.

Two viewport runs assert visible keyboard/mouse entry, no provisioning on dismissal/offline, one double-click registration, explicit later login with honest no-city state, duplicate-name unknown state, wrong-password rejection, known identity isolation, and no retry after a lost receipt/refresh/reopen. The server's explicit Login may create a player; Register alone may not. All city counts remain unchanged.

Only route names, response codes, equality booleans and numeric IDs enter JSON. Passwords are cleared before screenshots; raw frames, credentials, sessions and Playwright traces are not persisted. Failures are generic and evidence is written in finally. Independent runtime PG/sandbox/cleanup validation and pixel review remain required; this script alone is not proof of a successful run or complete new-player playability.
