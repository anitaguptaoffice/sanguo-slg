# Phase R2–R5：全量系统垂直切片蓝图与架构演进预留

本文定义 `R1` 完成后的完整 1:1 复刻拆解（共 19 个垂直功能切片），并明确数据库与领域接口的前瞻设计约束，确保各阶段平滑演进、无需推倒重写。

---

## 一、前瞻建模约束（R0/R1 施工时必须预留）

1. **多城感知键（Multi-City Ready）**：所有城池态接口与表（建筑、资源、人口、队列、驻军、城防、附属野地）一律以 `city_id` 为主键维度，严禁假设“一个 `player_id` 只有唯一一座城”。
2. **加成乘区解耦（Modifier Pipeline）**：内政产出、建造/募兵耗时、行军速度、部队攻防血射程统一采用可扩展 `BonusContext`（汇总：建筑基础 + 官职将领加成 + 书院科技加成 + 附属野地加成 + 道具 Buff），R1 先填野地与将领项，R2/R3 直接挂载科技与装备项。
3. **兵种与道具配置外置**：战斗与行军代码严禁 switch 写死 `unit_cfg_id == 1..4`，一律读取兵种表属性（`hp, ap, dp, range, speed, carry, people_need, food_use, category`）。
