# 客户端引擎：当前方案与备选

本文记录 **当前阶段** 已采纳的 H5 技术栈，以及 **尚未采纳** 的备选方案。美术样例、占位资源与 `spec/proto` 契约均按引擎无关设计，**不因本文档阻塞样例美术产出**。

## 1. 当前栈（本阶段）

| 项 | 选型 |
|---|---|
| 构建 | Vite |
| 语言 | TypeScript |
| 渲染 | Canvas 2D + DOM（面板、HUD） |
| 通信 | WebSocket + Protobuf（`spec/proto` 为真源） |

**为何本阶段保持该栈**

- 与现有 `client/` 骨架、网关联调、M2/M3 冒烟路径一致，迭代成本低。
- 主城与代表场景尚未用正式美术跑完性能验收，过早换引擎会放大返工面。
- 目标不是自研通用游戏引擎，而是 **薄渲染层 + 清晰业务边界**，便于日后只替换渲染实现。

实现入口见 `client/README.md`；目录约定：`src/engine/`（场景与绘制）、`src/net/`（协议与会话）、`src/scenes/` / `src/ui/`（流程与 DOM）。

## 2. 分层规则

```
┌─────────────────────────────────────┐
│  scenes / ui — 流程与交互（DOM 等）   │
├─────────────────────────────────────┤
│  engine — 渲染与场景生命周期          │  ← 可替换层
├─────────────────────────────────────┤
│  net + 领域状态 — 与 spec/proto 对齐  │  ← 引擎无关
└─────────────────────────────────────┘
```

- **业务与协议**：登录、选服、内政、军事、社交等只依赖 Protobuf 消息与纯 TS 逻辑，不绑定 Cocos/Pixi API。
- **资源契约**：路径、尺寸、图集切片等写在文档或配置中，与具体引擎资源管线解耦；正式美术进仓后由 `AssetLoader`（或等价模块）消费，**不**把引擎专有格式写进 `spec/`。
- **禁止**：在本仓库内建设「通用 SLG 引擎」或跨项目框架；`client/src/engine/` 仅服务本产品。

## 3. 升级闸门（何时再议渲染层）

在同时满足以下条件之前，**不启动**引擎迁移 PR：

1. **主城样例美术**（及约定清单内的 UI/图标）已接入当前栈，可完整走通登录 → 主城主流程。
2. **代表场景**（含世界地图或战斗表现等里程碑要求的高负载画面）在目标设备上完成性能验收（对照根 `README.md` 中的首屏与帧率目标）。
3. 形成书面结论：瓶颈在渲染层而非协议、资源体积或后端；且迁移收益大于联调与资产重导成本。

未过闸门前，客户端工作以 **样例资源 + 占位** 推进，文档与任务卡不得将 Cocos/Pixi 写成「当前已采用」。

## 4. 备选方案（仅作对比，非当前）

| 方案 | 定位 | 可能收益 | 主要成本 |
|---|---|---|---|
| **PixiJS** | 替换 `engine` 内 Canvas 2D 绘制 | WebGL 批绘、滤镜与粒子生态 | 场景与 UI 分工需重划；资源管线重写 |
| **Cocos Creator** | 编辑器 + 完整 H5  toolchain | 场景编辑、动画与发布流水线 | 工程与 CI 重塑；与现有 Vite 骨架分叉 |

二者均 **不是** 当前仓库的默认栈；若闸门通过后选型，应单独开决策记录与迁移任务卡，并保证 `spec/proto` 与资源契约仍引擎无关。

## 5. 决策表（当前 vs 备选）

| 维度 | **当前（已采纳）** | PixiJS（备选） | Cocos Creator（备选） |
|---|---|---|---|
| 状态 | 正在使用 | 未采纳 | 未采纳 |
| 渲染 | Canvas 2D + DOM | WebGL（2D） | 引擎场景图 |
| 构建 | Vite | 需评估（常与 Vite 共存或替换） | Creator 构建链 |
| 与 `client/` 关系 | 即 `client/` 现状 | 仅替换 `src/engine` 等渲染边界 | 可能独立工程或大规模迁移 |
| 样例美术 | **不阻塞**；按引擎无关契约交付 | 迁移后重导 | 迁移后重导 |
