# 架构

## 一、总体拓扑

```
   H5 客户端 (Cocos)
        │ WebSocket + Protobuf
        ▼
   ┌──────────┐
   │ Gateway  │  无状态：连接、鉴权、限流、路由
   └────┬─────┘
        │ NATS
   ┌────┴──────────────┬──────────────┐
   ▼                   ▼              ▼
┌────────┐        ┌────────┐     ┌────────┐
│ 游戏服 │        │ 战斗服 │     │ 调度服 │
│ 状态驻留│        │ 纯计算 │     │ 定时器 │
└───┬────┘        └───┬────┘     └───┬────┘
    └────────┬────────┴──────────────┘
             ▼
      ┌────────────┐   ┌────────┐
      │ PostgreSQL │   │ Redis  │
      │ 持久化     │   │ 热态   │
      └────────────┘   └────────┘
```

## 二、分服模型

「服」是天然的分片边界：

- 账号中心全局共享（一个账号可有多服角色）
- 游戏数据按 `server_id` 隔离，每服一个独立世界
- 跨服玩法（后续）作为独立服务，只读各服快照

扩容 = 加服，不需要分库分表。

## 三、域划分

| 域 | 职责 | 目录 |
|---|---|---|
| account | 注册、登录、多服角色 | `internal/account` |
| world | 地图、城池、野地、寻路 | `internal/world` |
| domestic | 建筑、资源、科技、队列 | `internal/domestic` |
| military | 募兵、行军、战斗、战报 | `internal/military` |
| hero | 招募、属性、忠诚、历练 | `internal/hero` |
| content | 道具、任务、商城、活动 | `internal/content` |
| platform | 网关、配置、日志、可观测 | `internal/platform` |

域之间只通过 `internal/api` 定义的接口通信，禁止跨域直连数据库。

## 四、关键设计

**1. 状态驻留 + 定时刷盘**

玩家状态常驻游戏服内存，操作只改内存，按间隔批量落库。避免每次点击都写库。

**2. 事件驱动调度**

用分层时间轮 + Redis ZSET 管理到期事件（建造、募兵、行军、战斗），
替代全表轮询。到期事件投递到 NATS，由对应域消费。

**3. 战斗独立部署**

战斗是纯函数：输入双方部队与将领，输出战报。无 IO、无状态，按 CPU 水平扩展。

**4. 协议先行**

`spec/proto` 是唯一真源，服务端与客户端代码由 protoc 生成，禁止手改生成物。

## 五、数据分层

| 层 | 存储 | 内容 |
|---|---|---|
| 静态配置 | 内存 + PostgreSQL | 兵种、建筑、道具、任务定义 |
| 玩家状态 | 内存 + Redis + PostgreSQL | 城池、资源、队列 |
| 日志归档 | PostgreSQL 分区表 | 战报、操作日志 |
| 排行 | Redis ZSET | 战力、声望、军团 |

## 六、可观测

- 结构化日志，`trace_id` 贯穿网关 → 域 → 存储
- Prometheus 指标：QPS、P99、在线数、队列深度、战斗耗时
- 本地 Grafana 面板随 `make dev` 起
