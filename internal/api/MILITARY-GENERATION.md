# Recruit and Return local source group

`API-MIL-SHARED-GENERATION-001` (#2422) composes only the already adopted
initialization-only source owners. `FRESH_CITY_PARTICIPANTS` section 2 requires
one admission controller and all-or-nothing local assembly.

The private constructor captures one Binding, immutable catalog and exact
43-object Return profile. Recruit gets its fixed 34-object projection. Both
children receive the exact same captured Binding address and admission before
initialization or publication; existing standalone constructors are unchanged.
Only both real constructor/pin transactions and confirmed rollbacks produce a
private pair. Neither child can be supplied by a caller or already initialized.

Group aliases share a one-shot owner. Failure or panic closes common admission,
invalidates both children and retains the original diagnostic/panic. Close is
serialized with pair publication and stops common admission before invalidating
children. SQL and draining never run under the group mutex. The existing
bounded cleanup and unknown classification remain authoritative: first-child
completion, cancellation, repeated close or waiting cannot resolve an unknown
second transaction. No reset, rebind, reopen or unknown-clearing path exists.

This is not enrollment, production writer exclusion, a business-attempt API or
a complete FreshCity generation. Future FreshCity participants and their fixed
inventory must join the same controller before complete-source publication.
No route, server, Hub, SQL migration, journal, attempt/completion or held source
is activated or adopted. Caller mutation during capture is unsupported; later
replacement of caller Binding, profile map or catalog cannot change the group.

Unit tests cover capture, exact pointer identity, projections, one-shot aliases
and shared lease bookkeeping. They are not real transaction evidence. The
separately registered PG companion must prove both real initializers, unchanged
tables/sequences, second-child failures and concurrent close, panic,
cancellation and retained cleanup uncertainty. Neither component may merge
before that exact composition passes independent review and ordinary/race PG
acceptance, with no skipped database tests, plus all required CI.
