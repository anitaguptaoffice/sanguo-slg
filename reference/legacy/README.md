# legacy —— 原版实现参照

本目录是**重构参照物**，不是可发布代码，不参与构建。

新项目是对原版 SLG 页游的完整复刻重构：玩法、数值、交互流程以原版为准，
代码、表结构、文案、美术全部重新实现。

## 内容

| 路径 | 内容 | 用途 |
|---|---|---|
| `server/` | 原版服务端 PHP 源码（732 文件） | 查某个玩法当初怎么算的 |
| `server/game/` | 业务逻辑，一个文件一组接口 | 规则细节的主要来源 |
| `server/config/` | 数据库、密钥、聊天服配置 | 环境参数对照 |
| `server/amfphp/` | 原版通信网关 | 理解请求分发模型 |
| `manage/` | 原版运营后台 | 后台功能清单参照 |
| `BandServer/` | 军团（联盟）服务 | 社交玩法参照 |
| `swf/` `BloodWar.swf` | 原版 Flash 客户端 | 界面流程、交互顺序参照 |
| `db/schema.sql` | 483 张表的结构（无数据） | 字段语义、关系参照 |
| `db/bloodwar.sql.gz` | 全量数据，69 MB → 压缩后 5.3 MB | 数值、任务、道具、名将等全部内容 |
| `db/TABLES.md` | 483 张表的行数与列数清单 | 快速定位表 |

美术资源在 `reference/art/`（另一个 PR）。

### 全量数据怎么用

```bash
gunzip -c reference/legacy/db/bloodwar.sql.gz | \
  docker exec -i rxsg-db mysql -uroot -p123456 bloodwar
```

数据里包含任务描述、名将列传、道具说明等文案，只作规则与数值参考，
新项目的文案需重新撰写。

## 怎么用

**查规则**：先在 `db/schema.sql` 找到对应的 `cfg_*` 表，再看 `server/game/`
里哪段代码读它，公式就在附近。

**查流程**：界面上的操作顺序看 `BloodWar.swf`，服务端的处理顺序看 `server/game/`。

**查数值**：`cfg_*` 表是数值的唯一来源。新项目的 `spec/data/` 是从这里提炼的初版，
不一致时以原版为准，再决定是否调整。

## 边界

- 只读参照，**不改、不跑、不打包**
- 新代码不得复制这里的实现，只借鉴规则与流程
- 文案、表结构、美术资源一律重新设计

## 注意

原版为 PHP 5.x 时代代码，存在已废弃的 API 与安全隐患（SQL 拼接、无参数化）。
参照时只看**规则**，不要照搬**写法**。
